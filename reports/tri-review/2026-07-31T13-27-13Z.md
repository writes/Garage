### Blocking findings

- The `while snapshot.sweepIncomplete` loop in `refreshQuotaStatus` executes network requests with no delay. If the server is slow or bugged, it creates a tight HTTP loop, causing a severe DoS risk and battery drain. Add a `Task.sleep` backoff.
- Hardcoding '$0.99' on the purchase button violates App Store Review Guidelines (3.1.1). Prices must be dynamically populated from `StoreProduct.localizedPriceString` to accurately reflect the user's regional currency and prevent rejection.

### Advisory findings

- `pollOnce` uses `try?` to swallow errors. Transient network drops during the final poll will falsely emit `.receiptCreditsGrantMissing`, polluting the ops metric for lost webhooks. Differentiate network errors from true server-side misses.
- If `store.purchase` succeeds but StoreKit throws a validation timeout, `markers.add` is bypassed. The purchase succeeds, but the UI flow won't explicitly resume, relying entirely on the background quota refresh to eventually grant it.
- If the SDK yields no transaction identifier on a successful purchase, `applyCreditsRecovery` is skipped. The user receives their credits, but the UI remains latched in a blocked state until they explicitly dismiss and reopen the sheet.
- Paywall dismissal relies on `currentUserID`. If an anonymous user dismisses the paywall and subsequently signs in, their UID isn't logged, preventing the credits offer from showing when their free saves are exhausted.
- The UI copy 'A previous refund left... this pack restores those first' might invite App Review scrutiny under Guideline 3.1.1, as Apple is historically strict about forcing users to pay back negative consumable balances.
