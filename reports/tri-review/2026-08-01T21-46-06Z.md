### Blocking findings

- ReceiptCreditsController leaves purchaseState=.idle when a resumed marker remains unknown. After the next quota denial, Buy returns, so an unresolved paid purchase can be charged again. Keep the offer suppressed while any marker is unresolved.
- MarkerStore prunes markers older than 72h before one final status/reconcile, deletes the transaction ID, and keeps the support flag only in the current controller. Reopening loses both the notice and repair key and may mislabel an already-granted purchase.
- Grant polling lacks an identity lease: resume captures a UID once, but pollOnce/applyTerminal re-read currentUID after awaits. An account switch can apply the old account's quota to the new sheet and resolve under the wrong UID. Pass and recheck the expected UID.
- A successful purchase with no transaction ID performs one generic refresh, never calls applyCreditsRecovery, creates no marker, and forces .delayed. An already-present grant leaves the quota latch blocked; a lost webhook has no transaction-specific reconcile path.

### Advisory findings

- refreshQuotaStatus retries sweepIncomplete forever at 400ms and runs before marker recovery. A stale server flag causes 2.5 calls/second and indefinitely delays paid-purchase repair. Use cancellation-aware exponential backoff and decouple marker recovery.
- Tests omit resumed-unknown double-buy, nil-ID recovery, UID changes during awaited polling/purchase, polling cancellation, TTL final reconcile, and sweep convergence. The named Firebase mid-purchase test changes UID only before a second purchase call.
- receiptCreditsPurchaseStarted is tracked before identity and product checks, contrary to its documented meaning. Identity-rejected and unavailable-product taps therefore inflate starts; track it after preconditions or define it as buy_tapped.
- UIDs and transaction IDs share one all-or-nothing UserDefaults JSON blob. Any decode failure silently discards every account's repair queue. Use protected per-marker durable storage with explicit migration and corruption recovery.
- HANDOFF.md is absent from the manifest although the included prior review records a same-PR handoff requirement and stale pre-client state. Refresh the HEAD, gate results, remaining blockers, and operator sequence before main merge.
