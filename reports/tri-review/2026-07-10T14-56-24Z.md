### Blocking findings

- Security & Information Disclosure: Passing the prompt (which contains up to 120KB of untrusted diffs and commit logs) via command line arguments (`-p <prompt>`) to `claude` and `agy` exposes source code and sensitive repository context to other local users viewing the OS process table (e.g., `ps`). Furthermore, it risks crashing the loop due to OS `ARG_MAX` limits, since the manifest and commit logs are completely uncapped. Standardize on STDIN for all LLM providers.
- Data-loss risk: `write_brief_atomic` contains a TOCTOU (Time-of-Check to Time-of-Use) race condition. It checks `os.path.exists(out_path)` but ultimately uses `os.replace`, which silently overwrites existing files. If concurrent processes target the same output path, one review report will be irrecoverably lost. Use `os.link` or `os.open` with `O_CREAT | O_EXCL` for true atomic creation without overwrite.

### Advisory findings

- Correctness: `is_protected_path` uses naive string prefix matching (`normalized.startswith(prefix)`). If a protected prefix is a directory like `src/auth`, this will falsely block edits to sibling paths sharing the prefix (e.g., `src/auth_utils.py`). Enforce a path boundary constraint.
- Correctness: `resolve_advisory` hardcodes `if len(valid) != 3: return 'DEGRADED'`. This breaks the `--reviewers` CLI argument, as requesting a subset of reviewers (e.g., `--reviewers claude,codex`) will always result in a DEGRADED verdict rather than properly evaluating the subset.
