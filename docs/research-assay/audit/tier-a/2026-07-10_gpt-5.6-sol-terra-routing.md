# Assay: GPT-5.6 Sol/Terra lane adoption (codex CLI ≥0.144.1) — Tier A

- **assay_id:** 2026-07-10_gpt-5.6-sol-terra-routing
- **date:** 2026-07-10 · **source:** operator directive (model routing v3) · **tier: A (ADOPTED)**
- **spec:** `docs/research/2026-07-10_MODEL_ROUTING_V3.md`

## Claim
Routing strategy/planning + votes + pre-main review to **GPT-5.6 Sol** and implementation to
**GPT-5.6 Terra** (both via `codex exec -m …`) raises verdict quality and implementation
throughput at $0 marginal cost (Codex subscription).

## Evidence (live, 2026-07-10)
- `codex exec -m gpt-5.6-sol` → `SOL-OK`; `-m gpt-5.6-terra` → `TERRA-OK` (codex 0.144.1).
- **Kill-relevant discovery:** on codex 0.143.0 both 400-ed ("requires a newer version of
  Codex") — i.e. the config default `gpt-5.6-sol` had silently broken EVERY codex lane until
  the brew upgrade. Machine-wide doctrine's "5.6 pending rollout — watch armed" fired here.
- First real workload: Sol produced a 10-blocking-issue strategic review of the routing spec
  (all triaged, 8 accepted); Terra implemented the routing change itself in a worktree.

## Death condition
Sol/Terra become unavailable on the subscription tier, or a measured verdict-quality /
implementation-quality regression vs. the prior GPT-5.5 lane → revert pins (one-line `BRAIN_*`
constants / env overrides), reassay.

## Revisit trigger
Any codex CLI major bump (re-probe both models — a stale CLI is a proven single point of
failure), or GPT-5.7+ appearing in `codex exec --help`/rollout notes.
